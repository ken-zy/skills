# 项目官方 X 公告：内置浏览器核验

macro 引用项目官方 X（原 Twitter）公告及其核验材料时执行；用于空投快照、TGE、升级、活动、延期和安全通知。仅按任务标的与时间范围查询，不给纯行情看板额外扫描社交动态。公司财报仍按 [IR 规则](company-ir-browser.md)，代币解锁仍须执行 [Tokenomist + DefiLlama 双源规则](token-unlocks-browser.md)。

## 读取与核验

1. 从已确认的项目官网/官方文档中的社交链接进入 X，核对项目、链及准确 `@handle`；记录官网入口和账号 URL。搜索只用于找官网/帖子链接，蓝标、显示名称、粉丝数、转发和搜索排名不能单独确认身份；创始人个人观点也不自动代表项目正式决定。无法建立官网关联时标“账号身份未核实”。
2. Codex 用 `mcp__cua_repl.js` 控制 `iab`，遵守初始化要求；优先复用标签页、后台读取；其他宿主无内置浏览器时说明不可用。打开具体原帖，检查作者、正文、线程上下文、原始图片/附件与外链；需要时展开长文或读取作者后续回复。动态页面加载后再读取，操作后刷新状态。只见摘要/链接卡片或附件不可读时，明确正文/附件未获取，不补写其内容。
3. 时间线的置顶帖、转帖和推荐回复不等于最新官方公告。限定目标期间，用账号帖子/回复及站内搜索定位更新、延期和更正；线程里仅将已核实作者的发言归于项目方，引用帖中的第三方观点分开。保留已读范围；搜索或部分时间线无结果不能证明全站或项目没有新闻。
4. 沿原帖链接读取官网公告、官方博客/文档或由官网/原帖链接确认的托管页面，核对事件对象、规则、日期、条件和修订。短链接须检查浏览器最终地址；保留入口、原帖与最终原文 URL。同一项目的 X、博客、托管活动页属于同源确认，转载同稿也不算独立信源。只有 X 单独公告时可写“项目方已宣布，其他材料未核实”，不能捏造第二证据。
5. 区分“项目方宣布的计划/事实主张”“宣传或预测”“实施证据”。用户数、收入、合作和性能数据先标项目自述；按所需结论另核统计口径、合作方公告或实际记录。涉及实施状态时，再按官网确认的链接读取治理执行记录、GitHub Release/网络公告或区块浏览器记录，核对网络、版本、合约/交易与执行状态。提案通过不等于已执行，软件发布不等于主网升级，计划快照/解锁不等于已发生；仅凭 X 宣称完成时注明“项目方称已完成，实施证据未核实”。

## 时间、状态与冲突

- 分开保存原帖发布时间、编辑/更正时间（页面提供时）、事件时间及读取时间。X 的显示时刻可能随浏览器本地化；可读取对应可见 `<time>` 元素的 `datetime` 字段；仅在含 `Z` 或明确偏移时换算 UTC，并注明来源，否则仍标时区未提供。不从帖子 ID 推算时间，不把未标时区的显示时刻直接当 UTC/北京时间。只有相对时间且无完整字段时保留原样并标精度限制。
- 事件时间保留原时区，转换时按事件日期处理夏令时；未提供时区/时刻就标缺失。快照、资格核算、领取开放/截止、TGE、交易所开盘各自记录；区块高度/epoch 不冒充已确认的精确钟表时间，预计换算须注明依据。
- 官网与 X 不一致时先检查发布时间、后续线程和适用对象。明确的官方更正只替换对应字段，保留旧值、修订来源与生效条件；无法解释则摘要提示“官方公告存在差异，待核实”，并列原值，不静默采用较新帖子或平均日期。
- 状态按字段写：官方计划已确认、仅项目方公告、预计/附条件、已延期/取消、已执行且有实施证据、未能核实。未来计划仍可能改变；安全事件原因/损失、收益和性能预测不能因官方发帖就升级为独立验证结论。

## 输出与访问限制

- 输出至少含：项目/账号及身份依据｜事件及适用网络/对象｜公告时间｜事件时间/时区及条件｜已核实事实与项目观点｜状态/差异/缺失项｜原帖及核验链接｜读取时间。同一事件合并展示，保留更正链和未解决冲突，不因新闻最多条数限制删去关键差异提示。
- 公开浏览器访问无需 API Key，可使用现有登录会话；未登录、验证码、限流、删除/受保护帖子或附件限制分别注明。普通加载失败可刷新或重开一次，仍失败停止该项；不反复重试登录墙/验证码，不为读取安装 MCP、购买 API 或订阅。
- X 不可读时，可继续用内置浏览器读取项目官网原文，明确“官网可读，X 原帖未能核实”；不能声称已完成 X 核验。没有官网材料则保留缺口，不回退外部 Chrome、API/MCP、隐藏接口、curl/WebFetch 或搜索摘要填补 X 内容。
- 任务只读公告，不关注、点赞、转发、回复、报名或订阅，也不连接钱包、签名、领取空投；此类动作需用户另行明确指示。
