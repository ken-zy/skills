# 公司 IR 与正式披露：内置浏览器核验

macro 的公司财报、投资者活动和公司公告按“第三方日历找线索 → 公司 IR 确认时间 → 正式披露核对内容”执行；不要求每次都先取第三方日历，已知公司/事件可直接进入官网。仅涉及公司事件或业绩时适用，不给普通宏观看板或代币新闻额外添加公司查询，也不改变其他子插件访问方式。

## 访问流程

1. 确认公司全名、股票代码、上市市场及目标财年/季度。第三方日历只作发现线索；引用 Yahoo 时执行其既有内置浏览器规则。搜索可定位公司官网/IR/原始披露 URL，搜索摘要和估算日期不能作为官方确认。
2. 通过公司官网的 Investors / Investor Relations 链接验证 IR 身份；不能只凭相似域名或搜索排名。官方 IR 链接到的托管站/CDN 文件可读取，但保留官网入口及最终文件 URL，不能称作独立第二信源。Codex 使用 `mcp__cua_repl.js` 控制 `iab`，遵守初始化要求；优先复用标签页，采集时保持后台，用户要求展示再显示。其他宿主无内置浏览器时说明不可用。
3. 在 IR 的 Events / News / Quarterly Results / SEC Filings 等区域读取事件或公告原文；按页面实际年份、筛选器和文件链接导航，不拼猜下一季 URL。先读取可访问性树，必要时使用可见 DOM 或截图；动态列表加载后再读取，操作后刷新状态再定位。
4. 未来事件由 IR 活动页或公告确认日期、时间、原时区、事件类型和计划状态；无官方确认的第三方日期标为“预计/未确认”，无时刻就写未提供。新闻/财报则读取原始公告，并按需要沿官网链接读取相应正式披露或在监管/交易所官网定位：美股可从 `https://www.sec.gov/edgar/search/` 按公司/代码/CIK 查找；其他市场用对应官方披露入口，不套用美股表单。
5. 正式披露核对发行人、文件类型（如 10-Q、10-K、8-K/附件）、报告期、提交日期及修订版，再定位所引用的财务表格/事项。优先可读 HTML；仅看到列表、标题或 PDF 下载链接不能声称读过全文。IR 托管副本明确标注，不冒称已在 SEC 官网独立核实；公司新闻稿与同稿附件也不能当独立交叉证据。

## 时间、数值与证据口径

- 分开记录：财年/季度及期末日、公告发布时间、财报计划发布时间、电话会时间、正式文件提交日期、读取时间。电话会时间不能填进财报发布时间；“盘前/盘后”是市场时段，不是精确时刻；财季不等于自然季度。
- 保留页面原时区；需要本地换算时依据事件日期核对夏令时，不能固定加减小时。读取时间带时区；页面未提供发布时间/时区就注明缺失。不要把网页更新日期当事件发生日期。
- 业绩比较必须对齐币种、单位、期间和 GAAP/non-GAAP，以及基本/稀释 EPS；保留调整项。IR 的管理层指引不是分析师一致预期，缺少可核实的同口径预期就不计算 beat/miss。公司前景表述标作管理层观点，不当独立结论。
- IR 与第三方时间冲突时，优先采用最新官方公告并注明差异及原日期；官方材料互相冲突时保留两份链接和发布日期，不能自行凑成一个时间。修订文件仅对其明确修订的项目优先，不能假定替换全部历史内容。
- 状态区分“已确认（官方计划）”“预计（第三方估算）”“已发布”“未能核实”；官方计划仍可能变动，临近事件重新核对。页面无结果、加载失败或未读全文不能推出“无重大新闻/尚无公告”。

## 输出与失败处理

- 事件字段：公司/代码/市场｜事件类型｜财年/季度｜日期/时间/原时区｜官方确认或预计状态｜公告发布日期｜官方及线索链接｜读取时间。
- 财务/新闻字段：报告期｜指标及口径｜原文事实与管理层观点｜IR/正式披露链接及提交日期｜已核验内容与缺失项。仅查未来活动不强制寻找尚未发布的财报。
- 每个页面加载失败可刷新或重开内置标签页一次；仍失败标记未获取/受限，保留其他成功材料。PDF/视频无法在浏览器中读取时明确正文未获取；不自动注册、订阅或接受协议。
- 不自动回退外部 Chrome/CDP 脚本、API、隐藏接口、curl/WebFetch 或搜索摘要读取 IR/披露事实。官网无确认时可保留已明确标注的第三方线索，不升级为官方事实。公开浏览器路径无需 API Key，不承诺所有公司网站均可访问。
