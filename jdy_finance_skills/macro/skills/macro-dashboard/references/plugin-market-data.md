# CoinGecko + Binance 插件行情规则

适用于 macro-dashboard、morning-note、news-digest 和 catalyst-calendar 的 CoinGecko/Binance 调用；引用当前加密价格时执行完整双源核验。仅在执行这些 skill 时核对并在当前报告中提示；不自动创建后台监控、不对外发送消息。这是调用指令，不能修复宿主或远端 MCP 会话。

## 工具路由

先发现当前会话中 CoinGecko、Binance 插件的工具并读取实际参数。用户指定 CoinGecko 连接时，只使用该连接；按宿主暴露的连接/插件来源核实身份，工具名前缀不能单独证明同一连接。身份无法核实且存在歧义时说明缺口，不改用独立 MCP。此限制仅针对 CoinGecko，不禁用 Binance 或无关 MCP。用户特定 app ID 放在本地任务配置，不硬编码进通用 skill。下面是 Codex 当前工具名；宿主前缀变化时按来源与功能匹配，不猜造工具或将旧 crypto 插件的 execute 当成同一连接。

| 数据 | 工具与参数示例 |
| --- | --- |
| 当前 USD 价格、市值、24h 涨跌幅 | `mcp__codex_apps__coingecko_get_coin_markets({ids:["bitcoin","ethereum","tether"]})`；单次最多 20 个 ID，含换汇币 |
| 全球市值、BTC/ETH 占比 | `mcp__codex_apps__coingecko_get_global_market({})` |
| 身份确认 | `mcp__codex_apps__coingecko_search_coins({query:"..."})`、`mcp__codex_apps__coingecko_get_coin_info({id:"..."})` |
| 新闻线索 | `mcp__codex_apps__coingecko_get_crypto_news({coinId:"bitcoin",limit:5})`；保留原始标题、时间和链接 |
| 历史价格 | `mcp__codex_apps__coingecko_get_coin_market_chart({id:"bitcoin",days:"7"})`；不可用无时间索引的 sparkline 推断精确区间涨跌幅 |
| Binance 现货价格 | `mcp__codex_apps__binance_get_spot_symbol_price_ticker({symbol:"BTCUSDT"})`；取 `result.price`，不是期货、标记价格或 AI 分析文本 |
| Binance 交易对核实 | `mcp__codex_apps__binance_get_spot_exchange_information({symbol:"BTCUSDT"})`；核实 baseAsset / quoteAsset、现货支持和 TRADING 状态 |

CoinGecko 优先解析 structuredContent.coins；Binance 优先解析 structuredContent.result；宿主仅给文本时解析其 JSON，并先检查 isError / error。空值、非有限数或价格 ≤0 均无效。

## 批量采集与本次报告复用

- 当前价格必须尝试 CoinGecko 与 Binance，不能在第一个成功后停止；不可用连接、硬限制或下面的停止条件使请求不能发起时，记录该缺口，不强行调用。可并行读取以减小采集时间差。
- 已知币种 ID 合并为一次 `get_coin_markets`；BTC/ETH 报告包含 `bitcoin`、`ethereum`、`tether`。最多 20 个 ID（含换汇币），只有超限才拆分；按返回 ID 匹配资产，不依赖响应顺序，不先搜索已知 ID。
- 成功的当前价格、24h 变化及同批 USDT/USD 汇率在本次报告复用，必须保持同一资产、区间和计价口径。时效不满足或价差需复查时，只能使用下述统一追加名额；不把上一报告的缓存充作本次数据。
- Binance 优先分别指定 `BTCUSDT`、`ETHUSDT` 等单个 symbol，不省略 symbol 拉取全部市场。批量 symbols 若返回 `Duplicate values for parameter 'symbols'`，逐币修正一次，失败批次已计入每个相关资产的调用预算；不重复发送同一失败参数。
- 全球行情、图表、信息与新闻只在报告确实需要时读取。不要先做健康探针，不用信息/新闻/搜索的成功宣称行情恢复，不用这些工具补取当前报价或另开请求绕过预算。

不自动回退旧 npx MCP、其它 CoinGecko 连接、直接 REST、浏览器或搜索新闻来补当前加密价格。有效单源值可保留，但须在摘要与价格旁明确“⚠️ 未完成双源核验：原因”；两源都失败则当前价格留空，不填 0。新闻仍可依原有官网/原文规则核实，并说明 CoinGecko 覆盖缺口；这不构成价格兜底。不读取、备份或索取 API Key；插件认证由用户在插件设置中完成。

## 错误分类、恢复与停止

先检查实际返回的 `isError` / `error`，保留原错误文本及可见错误码；不猜底层 HTTP 状态，也不仅凭包装码分类。下述停止/重连指定 CoinGecko 连接的分支针对 CoinGecko 错误；Binance 自身失败按其实际证据、受限范围与独立调用预算降级，不反向停止 CoinGecko。按以下证据优先级处理：

1. 明确鉴权、访问拒绝、计划限制或额度耗尽等硬限制，优先于泛化 429、会话文本和瞬时错误。401/403 与 session expired 同时出现，也不自动重连/重试。停止硬限制范围内尚未发起的请求，作用域不明时保守停止当前指定 CoinGecko 连接，不影响 Binance 或无关连接。
2. 具体限流/等待证据优先于模糊网络错误；明确 Session terminated / session expired 优先于通用 `INVALID_ARGUMENT` 或 JSON-RPC 32600 包装，不据此修改有效参数。
3. 无法消解的具体证据冲突，保留原错误并降级。不能把会话错误直接写成额度耗尽、参数错误、并发故障或已确认根因。

所有恢复动作还须满足下节共同等待、追加预算和停止条件。

| 分类 | 实际证据 | 恢复或降级 |
| --- | --- | --- |
| 会话不可用 | 明确 Session terminated / session expired | 将本次运行的指定连接标为会话不可用，立即停止新发其它 CoinGecko 请求。只有宿主实际暴露、已授权且不涉及权限扩大/凭据输入的重连能力时，重连一次并复测原失败请求一次；无该能力直接降级并提示重连。不得用改参数、换工具或换连接冒充重连。 |
| 短期限流 | 明确 429 / 短期限流，且无硬限制证据 | 服从共同等待约束；Retry-After 字段缺失时默认等 10 秒后原请求追加一次，不声称已遵守未知服务端等待值；字段存在但无法解析时降级，不用默认 10 秒覆盖。 |
| 鉴权/访问限制 | 明确 401、403、登录/权限/计划限制或额度耗尽（即使包装为 429） | 不自动重试或重连，说明具体缺口，不索取秘密；Cloudflare 拒绝/验证码不绕过。 |
| 瞬时错误 | 明确超时、连接重置或 5xx | 有明确等待信号时按共同等待约束；没有时等 5 秒，原请求最多追加一次。 |
| 参数错误 | 明确具体字段/格式校验，且无会话终止等更具体证据 | 仅按工具实际 schema 修正一次；通用包装码不足以换币或改资产。 |
| 无效/不完整数据 | 无 error，但缺必要 ID、有限正价格或有效换汇率 | 保留有效资产/字段，缺失项标未获取；原逻辑请求仅在追加预算内再取一次，仍无效即降级。 |
| 未知错误 | 不能归入上述类别 | 不盲目重试，说明错误未知并降级。 |

仅在一次合规宿主重连后，原失败请求成功，才将该连接恢复为可用并继续确有需要的 CoinGecko 请求。无重连能力、重连失败或复测失败，本次运行不再新发该连接请求；下一次运行重新发现工具并按实际结果判断。另一个在途新闻/搜索甚至行情请求成功，也不能代替这次重连复测开启连接。已经发出的并行请求不要求取消，其有效返回仍可依时效规则使用。

## 共同等待、追加预算与时间窗口

- 实际可见且可解释的 Retry-After 或其它明确等待要求，适用于受限范围内任何新请求，包括 429、503 等可恢复错误，优先于固定 5 秒/默认 10 秒。HTTP 日期按当前时间算剩余等待；不可解析时不猜更短值，说明等待未知并降级。
- 明确连接/账户级限制时，暂停该范围内所有尚未发起的请求（包含待发全球行情、图表和新闻）；作用域未知时保守暂停当前指定 CoinGecko 连接。Binance 与无关连接不受 CoinGecko 等待影响，不要求取消在途请求。硬限制优先，不能通过等待恢复。
- 可控等待每次最多 30 秒，且不得超过下述行情阶段剩余发起窗口。明确等待 >30 秒或窗口不够时，不截短等待、不提前调用；本次跳过受限范围待发请求并降级。没有行情需求的新闻调用仍遵守连接状态、等待和调用预算，但无需为计时先拉价格。
- 本次报告中，每个逻辑请求（同工具/币种集合/统计区间）最多 **2 次实际工具调用：首次 + 1 次追加**。错误恢复、无效数据复查、时效刷新和价差复查共用唯一追加名额，不能各重试一次。正常批次和其复查属于同一逻辑请求；不能改 ID 集合、拆成单币或多开其它工具绕过上限。Binance 失败批次后的逐币修正计入每个相关资产预算。合规宿主重连最多一次，不给行情请求增加名额。
- 行情阶段自首次行情请求发起起 **60 秒后停止新发调用**；价格、全球行情、历史图表及其追加请求均须在窗口内发起。时间上限约束模型可控制的发起/等待，不是宿主在途工具的强制超时。未暴露取消或网络超时参数时，不能承诺严格 60 秒内结束或编造取消结果。新闻阶段不能用于绕过受限连接、等待或价格截止。
- 请求已发起时就计数，包括失败；在途成功也计入。未发起的复查写“复查未执行：预算/时间窗口已耗尽”（或具体停止原因）；发起后失败写“复查失败”，不写通过。成功的新有效快照（含窗口结束后返回的在途请求）按时效规则使用；初次异常及其时间另留历史证据，不抹掉告警。

本次复测成功可写“此前会话错误，本次复测成功”；只证明该次调用可用，不能声称根因已确定、长期健康或双源/时效已通过。

## 同一资产、计价与时间

1. 已知映射：bitcoin ↔ BTCUSDT，ethereum ↔ ETHUSDT。其他资产先确认 CoinGecko ID、项目/链/合约（适用时），再用 Binance 交易对元数据核实；同名代币、包装币、杠杆代币不能直接当成原币。Binance 未上市、停牌或身份不明时标记“不可比较”，不可换用永续合约凑齐第二源。
2. 统一为 USD：CoinGecko 返回 USD；Binance 的 USDT 报价乘以同批 CoinGecko `tether.currentPrice`（USD/USDT）。明确记录该汇率来自 CoinGecko，因此换汇部分不是独立第三源。不能默认 USDT=USD；汇率缺失或无效则展示原币报价，价差留空并提示“计价未统一”。比较 USDT 本身时不可用同一个 USDT/USD 值构造第二源造成循环核验；缺少独立报价则不可比较。其他 quoteAsset 需取得明确方向的有效换汇数据，否则不可比较。
3. 每个源分别记录采集时间及源更新时间（若返回），不要把采集时间冒充源更新时间。请求完成时间差 >120 秒，或已知源数据距采集时间 >300 秒，视为不同步/过期；在统一追加预算和时间窗口内刷新相关数据至多一次，不能发起或仍不满足则不作有效价差判断并说明原因。未知源更新时间必须标注“源时间未知，以下仅为采集快照比较”；可以计算快照价差，但不能声称实时同步核验通过。
4. 本规则的 120/300 秒和下述 1% 是可由用户覆盖的工作默认值，不是交易所保证或投资标准。24h、隔夜、7d 等变化必须标明实际统计区间，24h 涨跌幅不冒充隔夜涨跌幅。

## 价差计算与告警

设 C 为 CoinGecko USD 价格，B 为 Binance 折算 USD 价格：

`价差百分比 = abs(B - C) / C * 100`

- 默认阈值 `1%`，用户指定时使用用户阈值并写入报告；以未四舍五入值判断 `价差百分比 >= 阈值`。
- 首次超阈值即保留“⚠️ 价格差异告警”，两源及换汇值同批复查至多一次，使用统一追加预算和时间窗口，不为已耗尽名额的源再发请求；不完整的复查不得当成同批核验通过。复查仍超阈值：标注持续；复查低于阈值：标注已回落并保留首次数值/时间；复查失败：标注“复查失败，未确认”；因预算、时间窗口或连接停止而未发起：标注“复查未执行”及原因；均不抹掉首次告警。不得因为没有源时间戳而静默丢弃超阈值快照，需同时提示时效不确定。
- 在报告摘要及对应价格旁显示：资产、两源原始报价和币种、汇率、Binance 折算 USD、价差、阈值、两源采集/更新时间及复查状态。不可用平均价格掩盖差异，不能直接断定任一源错误或存在可执行套利机会。
- 未触发阈值时显示价差；源时间未知则写“快照价差未超阈值（时效未核实）”。缺源、缺汇率、错资产、已知过期或不同步时写“⚠️ 未完成双源核验：原因”，价差为 N/A，不写成 0% 或通过。
- 市值/供给量等 CoinGecko 汇总指标保留原源；Binance 单一交易所成交量不与全市场成交量作同口径校验。

建议输出：

| 资产 | CoinGecko USD | Binance 原始价/币种 | 换汇率 | Binance 折 USD | 价差 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |

价格行附来源和时间；有异常时先展示告警再给分析。新闻/事件仍需通过原文、官方公告核实；插件未覆盖的解锁/快照/升级日历不能编造。
