# Tokenomist + DefiLlama：内置浏览器核对代币解锁

适用于 macro 四个 skill 及对应命令中实际引用的代币解锁事件。TokenUnlocks 现称 Tokenomist；只读两站公开网页，无需 API Key，不接入付费 API/MCP。不含解锁内容时无需额外查询。当前加密价格继续执行[插件双源行情规则](plugin-market-data.md)。

## 访问流程

1. 确认项目全名、代币代码、链/合约（页面提供时）、目标窗口及显示时区；不能仅凭同名代码合并。记录本次取单次事件还是窗口汇总。窗口默认为指定时区的 `[起点, 终点)`；用户给出含首尾日期的范围时，终点取末日次日 00:00，并写明约定。只有日期或时区未知的记录若可能跨越边界，保留为边界待核项，不猜时区后排除。Codex 使用 `mcp__cua_repl.js` 控制 `iab`，按工具文档初始化，优先复用标签页、后台读取；其他宿主没有内置浏览器时说明不可用。
2. 从 `https://tokenomist.ai/` 的 Token unlocks 列表/搜索进入目标项目，读取 Overview 的 Upcoming Unlocks、Unlock Events 及可见来源说明。按实际链接导航，不拼猜项目 slug。等真实事件字段出现且加载占位消失后采集；翻页、切换标签或筛选后重新检查组件位置及内容确已更新。可关闭普通宣传弹窗。
3. 同时尝试 `https://defillama.com/unlocks`，从项目列表进入详情的 Unlock Events 与 Notes；需要日历时使用页面的 View unlocks calendar。第一站成功也要检查第二站，不能把双源当先后 fallback。无需为了读取解锁去调用 TVL API。
4. 先按下述覆盖检查读齐目标范围，再按同一事件或明确的统计窗口逐项对齐；覆盖与可比性分别判断。引用项目 X 公告时按[官方 X 核验规则](official-x-browser.md)确认账号、原帖和更正。沿页面来源链接，用内置浏览器读取项目官网代币经济学、最新公告/治理决定；涉及合约证据时仅查看经官方链接确认的归属合约和链上记录。搜索只定位原始链接，不用摘要填数值或确认日期。
5. 只采集免费公开且实际可读的内容。遇到 Premium/模糊遮罩、示例行、占位数字或加载骨架时不得当真；DOM 能读出文本不代表该数据已开放。必要时截图确认公开区域，不解除遮罩或访问隐藏接口。付费字段记为受限，不自动注册、购买、申请 API 试用或连接钱包。

## 目标窗口覆盖检查

- 每站记录已查看的页码/分页位置、观察到的排序方向、展开/筛选状态及覆盖范围。检查可见上一页、下一页和相关展开项；默认页可能在历史或未来列表中间，当前屏不是完整列表。
- 观察到事件时间单调排序且相邻页顺序一致时，可以在目标窗口两侧取得范围外记录作为边界后停止；两边界之间的相关页必须连续读齐，目标页的相关接收方/分项也须展开读完。不得跳过中间页，不能用只读边界页来证明完整。经有效加载确认的列表起点/终点可代替对应一侧的范围外记录，记录页码、控件状态及所覆盖组件；仅一侧有证据不够。
- 筛选后的零结果只有在项目与窗口筛选已生效、加载完成且页面明确显示无匹配记录时，才是该公开组件范围内的有效零结果。空表、加载骨架、翻页按钮失灵、页码重复或内容停止变化不是列表端点或零结果。遇到可恢复缺页先按下述加载重试规则补采；仍失败则记录缺页位置和失败现象，不能把失败当成权限限制。
- 排序未能确认、速率变化节点列表、原时区未知或动态加载未完成时，不能仅靠两侧日期宣称完整。通过可见筛选/展开继续核查；巨大列表、登录/付费限制或操作失败使核查无法有界完成时，标“部分/未取得”，记录具体停止原因、已读范围和未读项。不要求无限翻页，不调用隐藏接口或绕过限制。
- “目标范围已检查”仅覆盖注明的公开组件与数据类型，不保证受限组件或全站数据完整。读完历史速率节点所有页，只证明那些页已读，不能证明目标窗口全部释放量已取得；两站均打开也不等于完成双源核验。

## 字段与口径

每个来源独立保留（可用 Markdown 表格）：项目身份｜来源与页面 URL｜读取时间（带时区）｜数据版本/更新时间（如有）｜原日期/时间/时区及精度｜目标窗口｜cliff（集中释放）/linear（线性释放）/速率变化/累计｜接收方/分配类别｜数量与单位｜百分比原标签/分母/时点｜组件位置/页码｜覆盖状态与原因｜计划/估算/实际记录证据。缺项写未提供。

- 用项目身份、事件或窗口、接收方及释放类型匹配；相同代币与日期不足以合并。Upcoming 单次 cliff、未来 7 天 emission、每天 linear 及月度合计不能直接比较。展开不全、接收方不全、时间语义/时区不明时保留原值并说明字段不足或口径不可比，不强行求和、平均或填零。
- 历史周释放速率是单位时间的释放量，不是该节点的一次释放数量；没有明确起止和速率变化证据，不外推本次月度总量。窗口汇总仅在覆盖足够、记录互斥无重复、类型和时间语义一致时计算，列出纳入/排除接收方。满足这些条件可计算明确标注的分项小计并比较同事件的匹配分组；小计不能冒充完整总量，cliff 窗口小计不能替代另一站不同分组的单次事件。
- `released/unlocked supply`、`circulating supply/float`、`total/max supply` 分开记录，不能都翻译为流通量。计算占流通量比例时用同一标的、时点明确且定义可核实的流通量：`该事件或明确窗口的解锁数量 / 流通量 × 100%`；说明分母来源/时间和是否解锁前口径。缺少合适分母就不计算，页面自己的其他比例可原样标注。
- 日历原有“解锁量 >5% 流通量标为高影响”仅作筛选规则；须满足上述可比条件并注明单次事件或累计窗口。分母不适合时不计算占流通量比例，也不触发此阈值；可根据影响范围和潜在供应规模另说明高关注，但不能声称通过 >5% 筛选。不能以占已释放量/总量替代，也不代表必然卖出或价格下跌。
- 分开记录事件时间、计划更新时间、行情估值时间和读取时间。只有日期/月份/倒计时就保留相应精度；不得倒推精确时刻，也不得把图表的 UTC 标签自动套给其他组件。模型从图表估出的分钟级时间仍是估计，不能升级为官方确认。
- 平台美元金额仅为页面估值快照，不充当新的当前价格来源；重算当前美元金额时按 CoinGecko + Binance 规则取得价格，保留数量、币价及时间。比较解锁先比较代币数量和口径，不以美元金额差直接判断计划冲突；行情 1% 告警阈值不套用到解锁量。
- 计划解锁、可领取、已领取、进入流通与已卖出是不同事实。日历不能证明链上实际执行；转账/余额变化也不能单独证明同一归属事件。两站可能都引用相同项目资料，Tokenomist 页面价格也可能来自 CoinGecko，不能称为完全独立的价格验证。
- FAQ/Insight 仅作待核线索，不能替代结构化事件卡片。不同组件的接收方、日期等不同，记录来源字段差异并核对项目原文；不自动选较新组件，不将不同日期/事件拼成一条记录。

## 差异核验与输出

- 先判断覆盖与可比性，再判断冲突。缺页/未展开要求补采或记录具体受限原因；口径不可比保留双方原值；同页卡片与 FAQ 的字段差异单独记录，不能自动升级为跨站事件冲突。只有同事件且可比的日期、数量等仍有差异，才检查时区、四舍五入、统计窗口、分组和模型假设；无法解释时在摘要提示 **“解锁数据存在差异，待核实”**，并列两站原值和口径，不静默选值或取平均。
- 回到项目原始材料核对版本、生效日期和后续修订。只有原文明确支持的字段才能标“官方计划已确认”；原文只有估计曲线时不能据此裁定某站精确日期/数量正确。不能因文件较新就假定它替换全部历史计划。
- 输出：事件｜Tokenomist 原值/口径｜DefiLlama 原值/口径｜项目证据｜状态/差异/缺失项。每条记录分别表达以下维度，允许同时存在，不用一个总标签掩盖其他缺口：
  - **采集覆盖**：目标范围已检查/部分/未取得，附两侧边界、有效列表端点/零结果或具体停止原因；注明事件表、图表或速率节点各自覆盖了什么。
  - **可比性**：同事件可比/口径不可比/字段不足，指出时间、类型及接收方的匹配或缺口。
  - **来源字段一致性**：一致/字段冲突待核/未取得，注明跨站匹配字段或站内组件差异。
  - **证据层级**：官方计划已确认/第三方估算待验证/未能核实/实际执行记录；官方确认仅覆盖原文明示字段，实际执行须有相应证据。
- 构建日历前检查两站窗口覆盖证据、分项/总量、事件匹配与分母定义/时点。未完整记录可作为明确标注的线索进入日历，不让单站失败阻塞其他可靠事件。摘要须保留影响结论的采集缺口、口径不可比、来源字段冲突及限制；新闻去重不能删除尚未解释的冲突。
- 加载失败可刷新或重开内置标签页一次；仍失败写加载失败/未获取，只有明确登录/付费证据才写对应受限。保留另一站成功内容并标“未完成双源核验”。两站都失败时明确无法核实，不能写成没有解锁事件。
- 不自动回退外部 Chrome、API/MCP、curl/WebFetch、隐藏接口或搜索摘要。公开网页免费部分可能变化，不承诺全历史/未来事件都可用，也不承诺实时或无限访问。
