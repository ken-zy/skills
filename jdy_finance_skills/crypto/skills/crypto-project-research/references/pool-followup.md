# 多池与对手资产后续调研

用于用户询问交易池、流动性、退出能力或比较不同池时。`snapshot` 和 `analyze.py` 的单参考池结果是市场底稿，不能代替以下后续调研。复用现有命名 `query`；不新增 Key、MCP 或依赖，不执行交易。

## 先确定覆盖范围

- 对快照发现的每个去重池列出地址、DEX、目标币所在侧、对手资产 CA、储备估值、24h 成交和后续状态。名称只用于显示；同名、同符号或不同链不得合并。
- 至少追查用户点名/截图的池，以及按储备、成交两种排序选出的主要池。按实际分布解释何为“主要”，不能只查成交排名第一的池。余下池可共用同一对手资产查询，或逐项标注尚未查及原因。
- 用户要求“其他池也查”时，应覆盖此前报告展示的全部池；若承诺覆盖所有发现池，就必须覆盖每个对手资产，不能用一个大池的研究代替其余池。
- 说明发现页数和是否到达空页；页面未穷尽时不能说“所有链上池”。按 network + 地址去重（仅合法 EVM 地址忽略大小写），不因同名或同费率合并不同池。

## 按确切合约追查后续兑换

1. 从已验证目标池的 base/quote relationships 提取对手资产的 network + CA，用 included 的地址核对名称，不能搜索符号后自动选币。稳定币和封装原生币也按确切合约确认；名称或符号不证明其兑付、锚定或发行人背书。
2. 对非终点资产请求 `token_pools` 并保存原始 envelope，例如：

   ```bash
   python3 scripts/fetch.py query --provider geckoterminal --endpoint token_pools --param network=NETWORK --param address=COUNTERPART_CA --param include=base_token,quote_token,dex --param page=1 --out COUNTERPART-page-1.json
   ```

   参数必须替换为已核验值；分页上限遵循 capabilities.md。若返回满页且未见所需终点，先在既定预算内继续分页，不能把第一页没发现写成没有市场。
3. 在相同链上识别稳定币直达池；必要时再追查一个有证据的桥接资产（如封装原生币）的后续池。默认探索范围为目标币→对手币→终点，或目标币→对手币→桥接币→终点，最多三次 swap；用户指定更长路径再按需扩展。终点资产必须在报告中写出 CA，不把 USDC 当成已经到账 USDT。
4. 每条路径验证相邻两跳共享的是同一 network + CA，列出每个池地址、资产方向、储备、成交、可确认的费率、采集时间与来源。排除返回目标币或重复资产的循环；只有终点真实接通才写“发现候选路径”。不能仅凭同名池拼接路径。
5. 共享下游池只记录一次证据，并让多条路线引用；不得将同一份下游流动性重复加总。各跳储备既不相加作为路线深度，也不简单取最小值宣称可执行容量。未统一币种/范围/时间，不派生路线排名。

不默认贬低其他对手币：`目标币/非稳定币` 可能连接到很活跃的稳定币市场，也可能未覆盖到；先查证，再区分证据与未知。以成交最活跃池作价格参考是采样选择，不是交易路由推荐。

## 保留状态与预算

状态使用明确含义：

| 状态 | 可以表达什么 |
|---|---|
| 已发现直达/多跳候选路径，未报价 | 每跳池与合约对应已核验；未证明实际可卖数量/滑点 |
| 查询范围内未发现终点 | 仅指已查页数与跳数，不能推出不存在路线 |
| 未调查 | 没有对应查询证据，不能说深度不足 |
| 请求失败/预算耗尽 | 原因与已完成范围保留，不能改写成零流动性 |
| 已取得指定数量的报价 | 仅在另行执行只读报价后使用；记录路由、输入数量、最终输出、费用、时间/区块、来源及报价性质 |

沿用客户端共享缓存目录和限流，不换目录绕过429。每批遵守现有180秒/12次尝试上限；较多对手资产可在明确的总体覆盖计划下分批，每批保存完成/失败/剩余项目，不通过重开批次绕过同一请求的重试上限。优先复用仍符合本次时效要求的证据，保留原始时间。所有时间范围需随报告披露，不能把多分钟采样说成同一秒状态。

免费池 API 不提供完整路由报价。本流程只能发现、描述候选路径。需要比较退出效果时，在相同输入数量、相近时间/区块和同一最终资产下另行获取只读报价；明确即时预估输出与用户设置滑点容忍度后的最低到账值的区别。没有该工具或数量就标注执行未验证，不假造滑点、不能卖或最佳路线。报价也不等于交易已成功。

## 最终报告必须补全

- 行情参考池的选择目的和数据范围。
- 逐池覆盖表，包括已调查的对手资产、候选终点和未完成原因；用户点名池不能省略。
- 后续池与候选路径表，能沿每条边追溯到具体合约、池地址和 envelope。
- 结论分层：已核实池/交易活动、由数据支持的解释、未验证执行能力。仅当证据实际表明某项不足时才作相应判断。

研究若纠正了旧结论，指出被纠正的是“参考池代表全部流动性”“中间资产必然限制退出”等具体推断；保留旧快照时间，不用新旧数据直接证明资金增减。
