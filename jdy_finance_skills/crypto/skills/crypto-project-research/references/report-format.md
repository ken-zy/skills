# 研究报告与证据文件

## 文件与状态

`fetch.py query` 写单个 evidence envelope；`snapshot` 写 manifest 和它引用的 envelope；`analyze.py` 读取保存的目录，写规范化 JSON 与中文 Markdown（`--out REPORT.md` 同时产生同目录的 `REPORT.json`）。两者均须尚不存在。每次使用新的输出目录/文件，保留原证据，勿将即时行情或凭据提交进 Skill 仓库。

envelope 包含 provider、endpoint、无凭据的请求路径/参数/source URL、原始 fetched_at、provider_date（如有）、cache_hit/expiry、attempts、HTTP 状态、结构化 status 和成功 data。空列表代表成功但无覆盖，不能转换成零价格。

manifest 描述 identity、起止时间、mode、参考池与选择理由、相对路径证据清单、分页/成交/K线覆盖、预算消耗和 warnings。读取失败、缺 Key、限流、超时与缺字段应按原因保留；部分失败不等于整个标的不存在。核心 token/身份未确认时不得输出该标的分析结论。

## 中文报告结构

1. **结论与边界**：本次数据支持什么；哪些问题证据不足。没有交易建议或自动评分。
2. **身份与截至时间**：名称、network + CA、已验证的可选 CG ID；采集起止时间、数据更新时间、缓存状态与范围。
3. **市场指标**：价格、提供商报告市值/FDV、分类型供给、token 汇总成交量；缺失留缺口。列明来源字段、计价币种与 scope。
4. **池与交易**：候选池、参考池选择依据、储备估值、24h 成交量、分页限制；目标 base/quote 视角。
5. **价格与成交窗口**：完成 K 线实际范围、缺口/未完成排除；区间收益、样本高低点和基于收盘价序列的最大回撤；成交样本数量、范围、去重/排除及样本买卖成交额差。
6. **集中度与安全信号**：可用字段与更新时间；其能证明和不能证明的事项。
7. **差异、失败与下一步证据**：接口差异、未知供给范围、缺 CG ID、未获取的审计/解锁等；不得以搜索摘要填补 API 失败后冒充同源当前值。
8. **来源**：可核查 API URL 或项目一手文档链接；数据时间与采集时间分开；必要的第三方数据延迟说明。

补充项目基本面时，保留“API证据 / 项目披露 / 分析推断”的来源区别。输出名称建议 `YYYYMMDD-token-{symbol}.md`，符号只用作显示，不作为身份。

## 比较报告

两个快照并排展示身份、指标和各自的时间/范围；列出 compatibility warnings。不兼容 scope、币种、供给类型或窗口时，不用派生比例、排名或涨跌结论掩盖差异。同一快照重复离线分析不应改变 K 线完成性。
