# 晨报覆盖与编辑分离方案

## 问题与目标

最近一版晨报只保留能源、SEC 托管提案和日历，压缩正文时也缩窄了采集范围。复查发现就业与股债背景、企业经营分化、与托管提案相反的准入诉讼、协议安全/退出事件、ETF 资金分化未完整进入候选池或评估记录。此次是工作流与提示规则修复，不新增行情程序、数据库或抓取服务。

目标：先完成指定范围的覆盖检查和候选核验，再形成 400–600 字、最多三条主线的领导晨报。不能保证全网无遗漏；必须能回答哪些类别已检查、哪些候选被选/合并/排除、哪些访问受限。短正文不要求每个类别都入选，更不固定重复旧消息。

## 用户边界

- 不采集任何代币现价/历史价/涨跌幅/换汇或双源价差，不汇报美股指数点位；不为展示而采集点位。
- 只输出标题、普通段落、来源链接；H1 主标题、H2 栏目、H3 重点，禁止星号强调、列表、表格、图表、图片、widget。保留北京时间日期、截止时间，通常两分钟可读。
- 网站正文与数值只用内置浏览器；搜索仅发现链接。CoinGecko 新闻只用既定连接并遵守共享请求/会话规则；新闻失败不等于无新闻。不通过新闻页报价栏补取代币价格：优先文章正文定位并排除行情栏，意外可见的报价不记录、不复用、不展示。
- DefiLlama 非报价免费 API 只在异常或核心论证确需时调用；ETF 流量通过浏览器，TVL 不是净流入。交易、外部发布和持仓推断均不在范围内。
- 本次开发允许更新 skills 仓库与既有每日晨报自动化；每次定时运行仍不得自行修改仓库。保留自动化 ID、线程、08:30 调度、状态和通知偏好。

## 覆盖先于编辑

每次运行先设北京时间截止时间与窗口（自上一期有效截止时间至本期；无法取得上一期时默认近 24h 并说明内部采用的窗口）。每个核心类别在内部记录状态、来源链接、已检查时间范围和候选结论：checked / partial / unavailable / not_applicable。checked 是指定来源/窗口完成检查，不是整个领域已穷尽。

核心类别：宏观与股债环境、重要公司/行业、能源与地缘、加密监管、协议安全/运营、今日与下一交易日的重要事件。各类至少尝试一个与窗口相关的可信来源；公司类先查重要动态线索，有候选再读 IR。可批量扫描综合新闻，但一个页面只能覆盖实际出现并核验的类别。某类无法读取时只换一个合理且合规的来源，仍失败则记缺口，不能无限调用或用搜索摘要填补。

重要 ETF／加密资金动态的新闻线索扫描明确归入加密监管核心类别的行业覆盖，可复用综合新闻扫描。是否进一步读取 ETF 流量明细或调用 DefiLlama 指标，由发现的线索及论证需要决定；未触发 not_applicable 仅适用于这些补证来源，不能代替 ETF 新闻线索检查。无法完成线索扫描时记录 partial／unavailable，已核实但未选入正文的候选保留排除理由。

条件性来源：FRED 在历史对比/序列需要时；FedWatch + Polymarket 在引用利率概率时；CNN 在引用情绪指数时；Tokenomist + DefiLlama 在重大解锁线索时；官方 X 在引用项目公告时；DefiLlama 指标/ETF 明细在流量或异常线索足以影响主线时。未触发记 not_applicable，不能声称已检查；核心类别不能整体冒用这个状态来逃避扫描。代币报价工具属于明确排除范围，不是缺口。

候选池保留事件日期、发布日期、统计期间/交易日、可核查原文、证据等级（官方/媒体转述/未核实）、新进展与既有背景，以及选入/合并/排除理由。最近十或二十条 CoinGecko 聚合新闻只是线索，不是全市场覆盖证明；若已检查窗口未覆盖关键类别或被预测/推广文章淹没，用内置浏览器补查对应新闻原文，而非反复加大插件请求。

核心类别扫描未完成，仍按时生成当期简报，核心结论与缺口相称。不设无宿主取消能力无法兑现的严格墙钟超时。内部覆盖记录默认留在当前运行上下文，只有用户询问来源/遗漏时才简洁展示，不新增持久状态系统。

## 从证据到主线

按影响范围、时效性、可信度排序，先选择最重要主线，再在已核实候选中检查会改变其判断的反证。不能只选 SEC 放宽而忽略同窗口的准入诉讼，也不能只写股涨而隐去影响结论的债券回落/融资压力。反证没有读到不能补造；存在重要覆盖缺口时不下全面判断。

合并相关事件但保留方向与口径差异：BTC/ETH ETF 流向不同不能写全面流入；单家公司改善不能写全行业复苏；一例资金追回不能写行业安全恢复；尚在征求意见/宣布/实施中的状态不能写已生效/已兑现。

周末最近交易日表现只作为背景，需要时一句带过。转载的新发布时间不重置事件日期；旧事件只有新增实质进展或对今日判断不可缺少时入选，并标旧背景。无新增时不为三栏目凑内容。仅在指定已检查范围内可称未发现重大新增，受限来源不得归为无新闻。

最终依次是今日结论、最多三条重点、今日关注 1–2 项；按事件日期核实并转成北京时间。只在核心判断受影响时用一句话说明缺口；分析措辞与事实/媒体转述分开，不机械标签，不给交易指令。记录压缩后未入正文的候选，不等于漏采。

## 验证与交付

方案交 ChatGPT Pro 内置浏览器审阅，保存原始意见与最终 PLAN LGTM，绑定方案文件 SHA256/字节数。通过后再交 implementation subagent 修改。

静态验收至少覆盖：核心类别缺失；监管利好与诉讼并存；周末旧收盘/转载；ETF 方向分化（初始候选池没有 ETF 事件，可访问来源中存在分化报道，实际执行应发现并纳入候选评估，访问失败则记缺口，不能未经扫描就记 not_applicable）；新闻页报价栏；CoinGecko 会话终止但浏览器新闻可读；关键来源受限。独立评估者只得到最终规则与原始场景，不给预期结论；检查实际输出和覆盖说明。链接、skill frontmatter、diff whitespace 校验不替代行为评估。

完成提交与 PR 后，把最终 HEAD 完整 diff、相关最终文件、自动化模板与待应用的路径展开后提示、实际验收结果交 ChatGPT Pro code review。保存 CODE LGTM 对应 HEAD 与包 SHA256/字节数；修复后重新审阅最终版本。核对最新 origin/main、PR 检查和冲突；变基有语义变化时重新审阅。按当前明确授权合并，证明提交进入 main，清理仅本次分支/工作区。

合并后同步原 skills main，应用已审阅的提示模板到现有 automation，再读取核对实际提示与调度；更新失败保留已合并代码并报告任务配置未生效，不冒称完成。默认只做离线行为验收，不自动另跑整份实时晨报，避免重复新闻或额外行情采集。
