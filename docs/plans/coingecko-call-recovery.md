让 macro skill 少做重复行情请求，并在连接异常时按可执行、有界的规则恢复或降级；当前用户指定的 CoinGecko 插件连接保持唯一，Binance 与无关 MCP 不受影响。改动是 skill 指令文档，不是 MCP 客户端或服务端实现，不能保证消除远端会话故障。

## 唯一连接与正常调用

1. 先发现当前工具并读取实际参数。用户指定连接时仅使用该 CoinGecko 连接；工具名前缀不是完整身份依据，按宿主提供的连接/插件来源核实。不能核实且有歧义时明确身份缺口，不改用独立 MCP。用户特定 app ID 只保留在本地调度，不硬编码进可复用仓库规则。
2. 一次报告需要的已知币种合并成一个 `get_coin_markets` 请求，BTC/ETH 晨报用 bitcoin、ethereum、tether。最多 20 个 ID；额外资产超限时才拆分，按返回 ID 精确匹配，不依赖响应顺序。
3. 在当前报告内复用成功返回的价格、24h 变化和 USDT/USD 汇率；不先搜索已知 ID，不使用信息/新闻成功作为行情健康证明。
4. Binance 分别指定 BTCUSDT、ETHUSDT，与 CoinGecko 采集可并行。全球市值、图表或新闻仅在该报告确实需要时调用；不通过它们探测行情错误，不重复取同一币种数据来凑信源。
5. 复用限于本次报告和同一时间/计价口径。最终报价过期、不同时或需要价差复查时进入统一追加请求预算，不能无限复用旧快照。新闻、图表、搜索不能补取当前报价。

## 错误识别与有限恢复

错误分类基于实际返回，不猜底层 HTTP 状态；同时保留原错误文本及能读取的错误码。若同时出现会话文本与通用 `INVALID_ARGUMENT` 包装，识别为会话错误；不能据此改参数。具体鉴权/限流证据优先于模糊“网络失败”。具体鉴权、访问拒绝、计划限制或额度耗尽等硬限制优先于泛化的 429、会话文本和瞬时恢复规则；401/403 与 session expired 同时出现也不自动重连或重试。无法消解的具体证据冲突，保留原错误并降级。

| 分类 | 识别证据 | 行为 |
| --- | --- | --- |
| 会话终止 | 明确 Session terminated / session expired 等文本 | 将本次运行的该连接标为会话不可用，停止继续发起其它 CoinGecko 请求。仅在宿主暴露、已授权且不涉及权限扩大/凭据输入的重连能力时重连一次，再复测原失败请求一次；没有该能力直接降级并提示重连。不得声称已重连或已修复。 |
| 限流 | 明确 429 / 短期限流返回，且无硬限制证据 | 按下面的共同等待约束；若等待大于 30 秒或超过允许发起新请求的时间窗口，本次不重试；未知 Retry-After 可等待 10 秒再试一次，不承诺遵守未知的服务端等待值。 |
| 鉴权/访问限制 | 明确 401、403、登录、权限、计划限制或明确额度耗尽（即使包装为 429） | 不自动重试、不索取秘密；报具体缺口。Cloudflare 拒绝/验证码不绕过。 |
| 瞬时错误 | 明确超时、连接重置、5xx | 有具体等待信号按共同等待约束；没有时等待 5 秒，原请求最多追加一次；不得改换连接。 |
| 参数错误 | 明确具体字段/格式校验错误，且无会话终止等更具体证据 | 仅按工具实际 schema 修正一次；不因通用包装码把有效 ID 改成另一资产。 |
| 无效/不完整数据 | 无 error 但缺必要 ID、有限正价格或有效汇率 | 已有效资产可单独保留；缺失字段标未获取。仅在行情追加预算允许时原请求再试一次，仍无效即降级。 |
| 未知错误 | 不能归入上述类别 | 不盲试，说明错误未知并降级。 |

实际可见且可解释的 Retry-After 或其他明确等待要求，是受限范围内任何新请求发起前的共同约束，适用于 429、503 等可恢复错误，优先于固定 5 秒/默认 10 秒。若是 HTTP 日期，用当前时间计算剩余等待；不能解析时不猜更短值，保留等待未知并降级。明确连接/账户级限制暂停其范围内所有尚未发起的请求；作用域未知时保守暂停当前指定 CoinGecko 连接。等待不超过 30 秒且剩余 60 秒发起窗口足够时才等待；超过任一条件不截短等待，本次跳过受限范围请求并降级。Binance 和无关 MCP 不受影响，不要求取消在途请求。硬限制仍优先于等待分支。

正常调用与追加调用统一计数：本次报告中每个逻辑请求（同工具/币种集合/统计区间）最多 2 次实际工具调用。故障恢复、数据无效复查、时效刷新及 >=1% 价差复查共用同一个追加名额，不层层嵌套。正常行情批次与其复查算同一逻辑请求；不能改集合或多开其它工具绕过上限。Binance 批量格式失败后逐币修正也计入相关资产的预算。

每个报告的行情阶段，在首次行情发起后 60 秒停止发起新增调用；限制的是模型可控制的发起/等待，不是宿主在途工具的强制超时。当前工具未暴露取消或网络超时参数时，不承诺严格 60 秒内结束，也不编造取消结果。可控的等待每次 <=30 秒。已发出的并行请求不能保证取消；其成功返回仍可按时效规则使用，不因另一工具失败丢弃有效数据。

一次会话重连后原失败请求成功，才允许继续确有需要的其它 CoinGecko 请求；复测失败或无重连能力，当前运行不再新发 CoinGecko 请求。各数据类使用各自实际调用结果，不能把新闻或搜索成功写成行情恢复。

追加名额已耗尽或 60 秒发起窗口已结束：未发起的复查标注“复查未执行：预算/时间窗口已耗尽”；已发起但失败标“复查失败”，不能把异常改为通过。成功取得的新有效快照（包括窗口结束后返回的在途请求）按时效规则使用，首次异常和时间另留历史证据。价差告警仍保留，不因预算耗尽或后续恢复而抹掉。

## 双源核验保持原合同

- CoinGecko USD、Binance USDT 原价和同批 tether USD 汇率明确标出；不默认 USDT=USD。
- 保持 120 秒源采集差、已知源更新时间 300 秒时效阈值，>=1% 价差告警、24h 与隔夜区分、源时间未知只称快照比较。
- CoinGecko 失败保留 Binance 有效单源值，计价未统一时不算 USD 价差；Binance 失败保留 CoinGecko。单源未核验状态必须进入摘要；两源失败留空，不写 0。
- 价差复查/时效刷新使用上述统一追加预算。初次 >=1% 就告警；复查回落也保留首次告警及时间，持续/未确认状态不能静默抹去。
- 本次恢复成功可注明“此前会话错误，本次复测成功”，只代表当前调用恢复；仍不确定根因，不表示独立双源或时效已通过。

## 验证与验收

这是一项文档指令改动，不编写镜像文案的测试或虚构执行器。采用现有仓库 validator、Markdown 链接/结构检查、`git diff --check`、完整差异人工审查和场景验收表。基线 validator 当前已存在忽略的私人 `.mcp.json` 缺失问题，实施前后记录同一命令的差异，不复制秘密配置补齐；新增错误必须解决。

场景验收必须逐项记录预期调用数、结果状态和复查许可：

1. BTC/ETH 正常批次：CoinGecko 一次含 tether；两条 Binance；有效数据复用，无额外健康探针。
2. Session terminated + 通用 INVALID_ARGUMENT：按会话错误；无宿主重连能力不重试，其他成功源可保留。
3. 宿主明确提供合规重连且成功：最多一次重连和原逻辑请求追加一次；失败则当前连接停止新调用。
4. 429 的 Retry-After=10/45/缺失：分别按值等待一次、降级、按明确默认等待一次，均不超预算。
5. 401/403：不重试，不将被阻止的独立 MCP 作为另一插件的根因。
6. 超时后成功：最多两次；其后遇到价差或过期没有追加名额，不隐瞒告警。
7. 正常初次 >=1%：一次复查；持续、回落、失败三个输出均保留首次告警。
8. 已知过期/源采集差超限：一次刷新机会；与价差或错误恢复共用预算；不能改 ID 集合重置预算。
9. 缺 tether、非有限价、缺某资产、缺源时间：单资产保留/未统一计价/快照时效未知，不填零、不冒称双源通过。
10. 60 秒窗口过期/工具没有取消能力：停止新发起，明确没有严格墙钟保证。
11. 其它 CoinGecko 连接存在：仍只用用户指定者，Binance/无关 MCP 保留。
12. 本次接口真实成功：记录工具参数、成功字段/图表点数和采集时间，只作为点时可用性证据；不能伪造故障重连的 live 测试。

13. 429 + 明确月度额度耗尽、401/403 + session expired：硬限制优先，不自动重试或重连；Session terminated + 通用 INVALID_ARGUMENT 原行为不变。
14. 503 + Retry-After=10/45/HTTP 日期/不可解析：按具体信号等待或降级，不使用固定 5 秒提前重试。
15. 连接级 429 后仍有全球行情/图表待发：受限连接全部尚未发起的请求遵守等待或本次跳过；Binance 不受影响；作用域不明也暂停指定连接。

2. PLAN LGTM 后才派适合的 subagent 执行范围内文档实现，验证并提交。主 agent 核对差异及完整方案完成情况。
3. 验证后推送分支并创建 PR；再由新的独立 ChatGPT Pro 会话审查完整固定 HEAD diff、必要全文上下文和验证证据。明确这是 skill 指令文档的 CODE review，不能声称有运行时恢复代码。要求 CODE LGTM 绑定 HEAD 与审查包 SHA256；修复后冻结新包并复审。
4. 用户已授权合并；只有固定 HEAD review 通过、最新 main 已包含且相应检查完成才能合并。不绕过仓库门禁。main 若变化，先同步、验证并对最终新 HEAD 再审查，不能沿用旧 HEAD LGTM。
5. 合并后验证远端祖先关系，快进主工作区并只清理本任务分支/worktree；其它任务的 worktree 保留。
6. 更新已有晨报调度，读取保存结果核对提示、08:30 计划、ACTIVE 与绑定会话保持正确；不重复创建自动化、不修改其他任务。
