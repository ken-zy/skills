## 方法与边界

不同于实现者的验证 subagent 完整读取 skill、command、weekly prompt 及单一展示规范和 11 份共享来源 references，分别用三个入口的完整指令对 dense/sparse/changes 生成九份报告。三个入口的摘要分别编辑，同案例的时间线、变化和证据正文用保存的写作脚本复用，每份报告仍有完整附录。生成和事后评估由同一验证 subagent 完成；这是 sequential 编辑验收，不是九次隔离模型调用，不证明随机稳定性、生产采集或用户阅读时长。root 另复读报告及合成输入、核查结构/事件/链接/原值。完整原始输入、执行请求、所读文件指纹、原稿脚本、输出和评估留在任务本地并提供给用户授权的 Pro CODE REVIEW，不公开本地绝对路径、真实用户报告或私密审查地址。

- dense：九事件逐一对应；CPI/BK1 电话会 20:30 叠加，财报约18:45分开；ET按事件日期的EDT换算、CHIP只有电话会、零售时区未知不补北京时间。HYX双方日期及链接、官方原帖缺口；ENB单次卡片和历史周速率不可比；PMP两组小计6.875B及社区24%TBD均前置并保留完整分来源四维记录，不将released supply冒充流通量、No Upcoming冒充全窗口零事件。SYN“10/15前”及资格/小时/时区未知保留。覆盖不足、主网TBD、无实施证据不被摘要预算删掉。
- sparse：仅一项重点/一行事件，不凑三项或6–10组；加载失败不称无事件，无基线不编造变化，仅日期不补时刻。
- changes：按语义身份匹配，输入编号变化不误配；A改期、B取消/替代未公布、C首次核验而非新公告、OLD范围外且无执行证据保留。C来源身份待核不影响保留输入给定日期。
- 九份初轮及四份复验均有摘要、变化、时间线、同报告完整附录；主表四列，摘要重点数分别3/1/2。摘要预算是软目标，未为补字数造事件；多项限制前置。长提醒和解释性措辞仍有继续压缩空间，未做真实阅读速度测试。
