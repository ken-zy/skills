# 制作方法

## 内容与画面

内容以用户提供的为准，默认不另查资料或核查事实。先按原页序或素材时间整理来源，再确定讲述主线、删减与假设例子。用自然口语、具体事件和因果推进；作者个人经历、史料、假设、主持人意见分开。旁白确认后做画面规划：每段写“对象—变化—观众应理解什么”和先后顺序，只定内容和顺序，不排时间，不以旁白每句配一张整图。同时在旁白里用半角竖线 `|`（全角 `｜` 也认）标出画面节拍必须换一条字幕的地方，如关键对象出现、转折处：`那天早上，|他发现日历被撕掉了一页。` 只标画面确实需要的；`|` 只决定字幕在哪断开，合成前去掉，对齐和逐字检查也忽略它；不要放在词中间。画面规划完成时，把确认的旁白逐句写进 `storyboard.csv` 的旁白行（`row_type=line`，带 `row_id`、`shot_id` 和 `|`），时间留空；对齐词时间读的就是这些行，排镜头表时再填时间、加对象行。

开头前 5 秒用一个具体场景或冲突切入，不先铺宏大背景。结尾最后约 5 秒默认向观众抛一个互动问题。不放卖书、购买或下单引导。

先按画面规划列出每个人物、物品和画板标记的最终态图稿，使用imagegen生图后集中审核；一张关键画面不能替代未覆盖对象的确认。简单对象同样需要确认图稿，已确认同款版本可复用。审核页显著展示全部相关角色与物品，不因折叠隐藏造成遗漏。图像提示词应指定身份特征、姿态、必要物件、简洁墨线、纯净底色、留白，以及删除密集排线；关键脸型和结构不减。不要盲目给出“最多几十笔”便宣称真实路径已达标。参考稿、动画线稿、批准版本分别保存。逐对象记录来源文件、区域／裁切、哈希和真实审核；人物头发、辫根、五官、服装等特征照稿保留。图稿错误先修图并确认，不用未核实的历史解释合理化画错；只修用户指出的对象或区域。

## 声音与时间

声音统一由 Voice Studio 制作与验收，详见 [Voice Studio接口](voice-interface.md)。白板侧交付确认文案、明确的声音配置选择与画面时点，接收真实版本化音轨、参数和清单；不默认B、不把自然短样当稳定长文默认、不自行研究克隆、训练、调速、降噪、笔声或混音。配置未选时先从用户已有选择或声音项目记录解析，不能落回CLI隐式默认。数字、专名、语气与前后音质等问题交回声音项目；完整音轨听审通过后才进入排时。

听审通过后对齐词时间，自动完成，不需用户参与。合成结果不带词时间，用 stable-ts（Whisper）把镜头表里已知的旁白文字对齐到旁白音轨 `narration.wav` 上，再按 jieba 分词合成词；字幕文字只取镜头表，不用语音识别的结果。强制对齐返回的就是给它的文字，脚本只核对返回的文字完整、不缺不多，不能发现录音读错或漏读；这些靠合成声音时用户听完整旁白发现。使用已验证的对齐环境及本地模型缓存；需要 stable-ts、jieba 与 Whisper，但不在 Voice Studio 环境里自行安装白板依赖，也不默认下载模型。缺依赖时按机器级依赖规则处理。运行：

```sh
python3 <skill目录>/scripts/align_words.py --storyboard storyboard.csv --audio audio/voice-v1/narration.wav --output word_timings.json
```

结果是 `word_timings.json`：`{"words": [{"text": "武昌起义", "start": 1.82, "end": 2.38}, ...]}`，时间是秒，和 `storyboard.csv` 同一条时间轴（整条旁白开头为 0）。不含标点；“1911”“袁世凯”这样的词不会被拆开。声音项目交付新旁白后，凡内容、时长或停顿改变，重新对齐、排镜头表和切字幕，不手工平移时间。仅混音更换而旁白时间轴未变时，按接口核对交付证据、时长与同步后才复用词时间。

排镜头表是把画面规划落到实测时间上，用真实 PCM／媒体时长：给画面规划时写好的旁白行填时间，再加对象行。镜头表每行只写一个对象或一句旁白（`row_type` 为 `object` 或 `line`），逐行填：所属镜头、文字或对象名、`audio_start`／`audio_end`、`draw_start`／`draw_end`、`recognizable_at`。旁白行有自己的 `row_id`，非空 `row_id` 全表唯一；对象行用 `line_id` 指向所属句子，`audio_start` 是旁白真正提到它的时刻（在所属句子的起止之内，常在句中），`audio_end` 留空，截止时间取所属句子的结束。画面优先：画面需要别的字幕断法（如某对象出现时要换一条），就在这一步增删或移动旁白行里的 `|`，文字、音频和词时间都不变；画面需要改音频本身（加停顿、重新分段），回 Voice Studio（第4步）。镜头表排定后才切字幕（见下文“字幕”）。

样片是整条旁白中连续的一段：从某句开头 T0 到某句结尾；还要让首个受审物品的第一笔完整进入片段，不能截在礼帽、后脑等已画完后。旁白音频直接从整条旁白音轨截取，不单独重合成或重新对齐；样片镜头表的时间是整片时间减 T0（以样片自身的 0 秒为起点），字幕在烧入时按同一 T0 截出（见下文）。对象可以提前画（`draw_start` 早于 `audio_start`）。可辨时间往往早于最后一笔完成时间。字段细节见 [审核记录格式](review-schema.md)。

硬门槛：旁白提到的对象在提及后 1.5 秒内可辨认（对象行 `recognizable_at - audio_start` ≤ 1.5，从提到它的时刻算），因此先画可辨外轮廓再补细节；画面静止不超过 3 秒，停留时用强调、圈画或移镜保持变化；每句旁白对应的绘制在该句结束前画完（`draw_end` ≤ 所属句子的 `audio_end`）。画不完先删装饰、减线、减对象或拆镜头，也可提高笔速；不加快旁白语速。不为了填满每秒堆砌新对象。排镜头表时先只给镜头表跑一次 `scripts/check_timing.py`（还没有视频，视频项记为未检查，看各行有无错误），样片和成片再连同视频核对；结果只作报告；“未完成”（缺数据、缺输入、片尾时长未知）不算通过。放宽门槛须用户同意。

静止检测对未烧字幕的视频运行，字幕变化就不会掩盖画板静止。局限：它比较整幅画面，手在动（没有出墨）也会让画面“在变”，掩盖画板实际没在画，所以不能代替人工按正常速度看片。

画板上的所有内容，包括人物、道具、装饰、标题、人名和关键词，都逐笔画出或写出，不淡入、不瞬间出现；文字能少写就少写。写字不能让手沿字形外轮廓描边冒充笔顺。

## 字幕

字幕不画进画面，也不进镜头表；它不是画板内容，不受逐笔规则约束。画板上的文字仍逐笔写。

1. 切字幕并锁定：镜头表排定后（旁白行填好实测 `audio_start`／`audio_end`，文字带画面规划时标、排镜头表时调整过的 `|`），只切这一次，不需要视频：`python3 <skill目录>/scripts/make_srt.py --storyboard storyboard.csv --words word_timings.json --output subtitles.srt`。
   - 断句：每句先在 `|` 和标点处断；一段超过 `--max-chars`（默认 16 字，单行）时，在词与词之间切成尽量等长的几条，不拆词；切点不放在虚词旁：一条不以“在 把 被 将 对 从 向 和 与 及 或 但 而”结尾，下一条不以“的 地 得 了 着 过”开头，实在避不开就照均衡切并提醒；不足 0.8 秒的短条（如“接下来，”）在放得下时并入相邻一条，中间的标点显示为空格；短条不跨 `|` 合并，`|` 造成不足 0.8 秒的短条就报错（画面明确要这个断点，不悄悄合并），移动或去掉该断点。`|` 不显示。行尾的逗号、句号、分号、冒号、顿号去掉，问号、感叹号保留。
   - 时间：每条从首词开始，句内停顿时上一条留到下一条出现，一句的最后一条到末词结束。
   - 自动检查（不需用户审字幕）：每句各条拼起来去掉词间标点后与旁白逐字相同，不多不少，词内的字符（如 `3.5` 的小数点、`10:30` 的冒号）原样保留；每个词都在本句 `audio_start`～`audio_end` 内（容差 0.1 秒），词按时间先后排列、互不重叠（容差 0.02 秒），词时间里的每个词都恰好属于一句旁白行（镜头表漏了旁白行就报错）；条与条不重叠；每条不超过字数上限；每条至少显示 0.8 秒，不够时在不重叠的前提下延长，没有空隙就报错；每秒超过 12 字视为对齐可疑。缺词时间、词与文字对不上也报错。
   - 有任何问题：列出问题、不写 `.srt`、退出码 1；回排镜头表改断点，问题在音频就回 Voice Studio（第4步）。脚本只读输入，已有文件不覆盖（确需覆盖加 `--force`）。
   - 通过即锁定：把脚本打印的 SHA-256 写入 `episode.json` 的 `subtitles`（`{"path": "subtitles.srt", "sha256": "…"}`），样片和成片的 `dependencies` 都登记 `subtitles.srt` 及这个哈希。之后不手工改字；确需改字幕就回排镜头表，改好再切一次、重新登记，并重做依赖它的样片检查和烧入。
2. 烧入（样片、整片的最后一步）：先对无字幕版跑完 `check_timing.py`，再做轻量检查，只核对 `subtitles.srt` 的哈希与锁定时登记的一致、所有字幕都不超出视频流结束时间（不是容器时长），不重新生成或切分：

```sh
# 整片：通过后原样烧入 subtitles.srt
python3 <skill目录>/scripts/make_srt.py --check subtitles.srt --sha256 <subtitles.sha256> --video render/成片-无字幕.mp4
# 样片：T0 为样片在整条旁白里的起点；截出该段并平移到样片的 0 秒，写成 render/样片.srt
python3 <skill目录>/scripts/make_srt.py --check subtitles.srt --sha256 <subtitles.sha256> --video render/样片-无字幕.mp4 --start <T0> --output render/样片.srt
```

`--start` 须为非负有限秒数。样片起止切在某条字幕中间时报错，改样片起止，不改字幕。检查通过后输出新文件，保留无字幕版。字幕样式使用已确认的苹方 SC Regular，1080p参考46px、底部居中、深灰色、无描边；直接叠在浅暖画面上，无底栏和分隔线。明确选择简体字体face并检查实际输出，不能仅凭TTC文件名或默认索引认定字形；不同渲染器的字号单位可能不同，不照抄未验证的数值。采用已审核的烧字实现；本机缺libass时可用已有Pillow按锁定SRT绘制，选择字体face后验证其名称及边界，不为烧字幕安装新渲染环境。其他画幅的大小与位置用样片验证。找不到确认字体时说明并提交替代样片，不静默回退，也不复制系统字体到素材仓库。

烧入的文字只来自检查通过并已锁定的 `subtitles.srt`，不手工改字、不另行生成。字幕时间来自对齐出的词时间，精确到词，不是逐字。烧入后抽帧看字幕位置、字体和边界。

## 路径与手部

先绑定确认图稿，再组织语义笔顺，不因对象简单就跳过生图审核。可用原生路径作为绘制实现，但完成态必须与确认来源一致，不能另画成简化几何人物或道具。每个保留墨线区域都要由实际接触笔画逐步出现，不以末帧贴完整图补齐。

人物先建立头脸、衣领与身体主轮廓，再五官、头发／辫子等特征；服装先主要外形，再领口、衣襟、口袋和细节。数字按阅读顺序逐字完成，并按字内笔顺书写；圆环和交叉部位安排连续性与先后归属，不沿外轮廓绕圈描字。骨架或邻近排序仅辅助定位，不能代替主笔顺。细排线仍需正常速度检查，不把数值保真当作人类笔顺通过。

箭杆、回转线、箭头和强调线按主线顺畅完成，避免重复回描和自动碎线补画；分叉按清楚的方向与先后组织，不将某一箭头的固定笔数或速度推广到所有图形。

落笔期间手和笔尖可见，笔尖与出墨端共用时间。保持同条线误差固定，避免逐帧抖动。短距离提笔可顺畅换位；等待、跨区域或长距离换位时收起手和笔，下一笔再出现，不悬空乱移来掩盖画板静止。画板内容本身不淡入淡出。检查前臂截口与遮字，必要时柔和收起手部而不是加字幕色带；固定持笔素材只能表达加速绘画，不能声称是真实手指关节动画。

同一视野保留已画内容；按主题分区、平移或回看，不把全片挤满一板。手收起后可留可读时间，但画板静止仍不超过3秒。样片包括首个受审对象的完整首次绘制，不截掉笔画起始；回看已画对象与首次展示分开记录。新路径、后端、手部或字幕版式用同段样片验动态，再扩展整片。

## 音轨接口和交付验收

向 Voice Studio 提供实际触笔／提笔区间、对象和笔画ID、场景转换、统一时间原点、总时长及样片T0；接收其交付并验收的音轨，不在渲染器内制作摩擦噪声、合成音床、调音量或滤波。笔声只在接触时出现、提笔静音；音量引用本集已确认声音版本，不把一次降低的分贝数作为通用默认。声音问题连同具体时间、版本和同段视频回交声音项目，参见 [接口说明](voice-interface.md)。

样片使用计划用于整片的声音交付，实际编码后的音画效果由用户听审。声音项目可提供同段分轨对照；无法实际听到时说明未验证，不把轨道非零、哈希相同或截图写成声音通过。任何后续否定意见更新该版本状态，不能沿用较早的“可以”覆盖新问题。

成片用现有 ffprobe／FFmpeg 检查完整解码、时长、帧率、峰值、字幕边界和音轨同步；抽查绘制中及完成帧与确认图稿，并正常速度看片。检查不通过就修正实际产物，再做受影响检查；不只更新报告。保护对象按清单核对未变。

交付包含当前步骤、版本／路径、修改点、检查结果、未验证项及下一审核节点。审核页让相关人物和样片容易找到，提供可直接打开的本地音视频；验证媒体实际加载、正常播放和可拖动。若使用本地HTTP，需支持音视频字节范围请求；浏览器验证只是功能检查，不代表已通片听审。本地服务失效时恢复入口，同时保留直接文件入口。

旁白时间未变、只换验收混音时可复制原视频流；只改画面则先确定相关依赖，不承诺只改一句就只算一帧。定稿冻结音视频与输入版本，后续修订使用新目录。
