# 工程参考与保护

参考工程属于当前项目，不随 skill 固定。先检查实际存在；路径缺失时仍可用本 skill 组织流程，不伪称已有渲染后端，也不无提示地安装整套第三方项目。受保护对象、定稿哈希、禁止运行的命令和归档位置一律以项目的 `docs/videos/PROTECTED.json` 为准；具体参考文件入口写在项目自己的文档里（如同目录的 `REFERENCE-NOTES.md`），skill 不写任何某一集专属的路径。

## 只读参考入口

开工前在项目内查找：`docs/videos/PROTECTED.json`、其 `notes` 指向的参考说明，以及各集目录的 `README.md`。只读阅读，按其说明选择要借用的渲染和手部模块、图稿及音轨交付元数据。项目没有这类文档时，不套用其他项目的结构。

声音模块归 Voice Studio（见 [调用接口](voice-interface.md)）；白板侧只复用实际交付的音轨与对齐数据，不复制克隆、滤波、音效或混音实现。版本会变，按实际环境核查，不要把以往的版本豁免变成长期保证。

## 适配新视频

1. 在新集目录开发。旧工程只读，先列需要的模块和素材，再复制必要依赖到新集内部；不要复制整个旧故事当已完成的新集。
2. 参考工程可能存在多层导入，以及人物、持笔手、字体和声音路径依赖（具体链路见项目文档）。导入可能加载旧图，缺配乐时的回退可能写旧样片 WAV。复制视觉模块后逐一重定向读取／输出路径，禁止指向旧集可写路径；声音模块不导入到白板渲染器，不启用会自动合成音床／混音的旧工程回退。
3. 替换新旁白、分段、角色、镜头、字幕和所有语义时点；不得让新主题播放旧旁白。asset ID 与新故事一致。JSON 工作表是编排与审核记录，需要 Agent 实现适配代码，不是声称现有 renderer 已能消费这些 JSON。
4. 输出目录必须按版本新建，拒绝覆盖已有视频；预览也只能写新集目录。先用计划中的最终引擎做代表片段，经过用户审核再扩展。
5. 现有本机可用过 Python 3.14 的 Pillow／NumPy 环境；默认 python3 可能不是它。先探测已装解释器和 ffmpeg，不为导入失败立即重装或升级。辅助脚本只用标准库，`align_words.py` 例外（需已有stable-ts／jieba环境与模型缓存，见 [制作方法](production.md)）；实际渲染依赖需按机器政策核查。

## 保护清单

项目含 `<项目根>/docs/videos/PROTECTED.json` 时，开工前先读取：

1. 清单 `protected` 中每项的 `path`（目录或文件）都只读。只读查看、核对哈希允许；禁止在其中创建新集、覆盖文件，或原地运行渲染、混音、预览、语音脚本。`do_not_run` 列出的命令绝不在原位置执行，包括其预览模式。
2. 用 `shasum -a 256` 核对 `files` 中每个文件。值不同就停止任何会触及该对象的工作，报告差异，不自动用旧版本覆盖。新集工作与该文件无关时继续在新目录制作。
3. `archive` 记录中间文件归档与备份位置。正常新片不必下载归档或恢复旧音轨；确需读取时校验清单，解压到隔离目录，不回填受保护目录。
4. 没有清单时按一般规则：已定稿／暂定定稿目录只读，修订另建同级版本。清单本身也不由 Agent 擅自修改；新增定稿需要保护时，经用户确认再写入。
5. 清单无法读取、是悬空软链接或不合格式时，视为“保护状态未知”：停止建集和任何会触及项目旧集的写入，报告问题，由用户修复清单；不得当作“没有清单”继续。
6. skill 与项目清单（及清单引用的项目参考文档）必须一起写回、一起部署：skill 不再写死受保护路径，只写回 skill 而漏掉清单，旧定稿会失去保护。

格式（`schema_version` 必须是整数 1；路径一律为相对项目根的相对路径，不得是绝对路径、不得以 `~` 开头、不得含 `..`；项目根即清单所在 `docs/videos/` 的上两级，`project_root` 仅作记录）：

```json
{
  "schema_version": 1,
  "project_root": "/项目绝对路径",
  "protected": [
    {
      "path": "docs/videos/集目录",
      "reason": "为何只读",
      "files": [
        {"path": "docs/videos/集目录/定稿.mp4", "role": "final_video", "sha256": "64位小写十六进制"}
      ],
      "do_not_run": [
        {"command": "会写回文件的脚本或参数", "note": "原因"}
      ],
      "archive": {"path": ".archives/归档目录/", "release_url": "备份地址", "note": "使用规则"},
      "notes": ["其他只读说明"]
    }
  ],
  "notes": ["整个清单的说明（可选）"]
}
```

`init_episode.py` 只查保护所依赖的部分：JSON 能解析、文件不是悬空链接、`schema_version` 为整数 1、`protected` 是列表且每项 `path` 为相对路径、`files` 是列表且每项 `path` 为相对路径、`sha256` 为 64 位小写十六进制。其他字段（`reason`、`do_not_run`、`archive`、`notes` 或新增字段）供人和 Agent 阅读，脚本不校验，也不因未知字段拒绝。

保护的定位：防误操作，不防故意绕过。清单和 `init_episode.py` 用来挡住在定稿目录里建集、原地运行会写回的脚本这类失误；多层软链接等刻意绕法不在处理范围内。

`init_episode.py` 的保护规则（全部在写入任何文件之前完成）：

- 分别从输出路径的“输入形式”（不解析软链接）和“真实路径”（解析软链接后）逐级向上查找所有 `docs/videos/PROTECTED.json`，每一级都收，不在第一个清单处停下；`--protected` 指定的清单只会追加，不会替代查到的清单。
- 每份清单按上面的必需项检查；任何一份损坏（含悬空软链接、`files` 写成对象、版本错误、绝对路径）即以非零退出码拒绝。输出路径含 `..` 段也直接拒绝。
- 用真实路径（并同时用输入形式）判断输出是否落在任何清单所列路径内；只要有一份清单判定受保护就拒绝。里层空清单或另指一份空清单都不能覆盖外层清单。
- 它不核对哈希；哈希仍由 Agent 按第 2 条核对。输出路径既不经过项目目录、又不在项目内时，脚本查不到清单，需 Agent 按第 1 条自行核对。

本人声线的可用性、版本和验证范围以 Voice Studio 当前交付为准；不把某条样音历史认可推广成所有文案／时长都稳定。数字形象单独验证。
