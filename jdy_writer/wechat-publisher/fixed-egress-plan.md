## 拟实施变更

1. 本机 Clash 当前持久 profile 和生成的运行配置各追加一个 listener：名称 `wechat-publisher`，HTTP，监听 `127.0.0.1:17993`，`proxy: 固定美国`。保留所有原有节点、选择、规则、DNS、TUN、listeners、系统代理和全局环境。
2. 发布器新增无密钥网络配置文件支持：`~/.config/jdy-writer/wechat-network.json`，本机设置代理 `http://127.0.0.1:17993` 和预期 IPv4 `95.169.12.176`。该文件只含网络参数，不接触公众号凭据文件。
3. 新增小型网络模块，配置缺失时保留原有发布行为；配置存在但无效时中止。配置在一次发布开始时读取并冻结。只接受无认证信息的 loopback HTTP 代理与合法的预期 IPv4。
4. 发布器在非 dry-run 路径、加载公众号凭据前，经指定代理查询国内和海外 IP 探针；两者必须与预期 IP 一致，否则中止。探针失败、代理关闭和出口错误均不回退直连。
5. 三处微信 API 调用（覆盖 token、uploadimg、add_material、draft/add 四个 endpoint）统一使用一次发布内绑定的 fetch：显式 Bun `proxy: {url, respectNoProxy: false}`，即使环境存在 NO_PROXY 或其他代理也固定走专用入口；禁止重定向并设置请求超时。不替换 globalThis.fetch，不修改进程环境。R2/正文源图片下载及 Markdown 渲染维持原有路径。
6. 正常 dry-run 不加载网络配置、不探测出口、不调用 loadCredentials 或读取 `.env`；保留原有 EXTEND 账号元数据解析行为，不声称从未读取任何可能包含账号字段的配置文件。既有导出图片处理函数和测试可继续独立调用。
7. 更新技能中的公众号流程，记录设备本地配置、预检和恢复方法；不修改 X 流程、文章正文、计数器、风格档案或其他技能。
8. 微信网络包装层统一转换错误，只输出受控阶段、错误类型、HTTP 状态、微信数字错误码和经过 IPv4 校验的白名单报错 IP；不传播原始异常对象、完整 URL、原始响应体或未经清理的 errmsg。成功响应仍仅打印发布器必要的 media_id 等非凭据结果。
9. 草稿成功响应必须包含非空 media_id，否则报受控错误，禁止 success:true 与计数递增。对失败响应和网络异常，使用假 AppSecret/token 哨兵测试最终输出的脱敏结果。
