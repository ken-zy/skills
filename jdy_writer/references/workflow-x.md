# X 中文内容与发布

仅执行用户要求的写稿、保存或发布步骤。已选定的形式、正文、图片和授权继续有效，不在公众号结束后自动进入 X，也不再次询问是否带图。

## 内容形式与定稿

- 用户要求改成 X 中文内容时，可以压缩、改写；沿用作者声音检查，保留真实经历、判断及收益/归因的证据边界。未要求改写时保留原稿。
- 区分普通短帖、单条长帖、Article 和多条 thread。超过短帖长度不自动转 Article；优先按用户选择，在账号编辑器中检查实际可用能力。无法容纳全文时停止并说明，不擅自截断或拆帖。
- 草稿保存在公众号文章同目录 `{YYYYMMDD}-x-post-cn.md`，不新增 YAML；保留 `## 关联` 和与来源文章的双链。
- 定稿前展示完整正文、图片及顺序。长帖附件最多四图；用户说“所有截图”时逐张核对原素材，不混入生成封面；超过附件上限时说明并取得取舍，不能漏图。
- 正文保留自然段和用户确认的排版，不机械地把每个句号变成换行。图片中的社区测算、推测归因在必要图注中保留限定，不升级为事实。

## 固定浏览器与账号

单条帖子使用内置 `x-publisher/x-browser.ts`。默认稳定版 Google Chrome、`~/.local/share/x-browser-profile-cn`，账号为 `@_ThrowException`。不再默认共享 baoyu profile，不通过环境变量静默换浏览器或 profile；显式 `--profile` / `--chrome` 仅用于用户已指定的配置，账号校验仍生效。

每次读取页面中的账号身份。发现登录失效时保留专用窗口、标签页和回执，请用户在窗口登录；登录后使用原命令与原回执继续，不读取或导出 cookies、token。账号不符则停止。

只新建本任务标签页，不覆盖其他草稿。恢复时复用回执中的标签；编辑器非空且不属于本次已准备内容时不清空、不追加。

## 单条帖子的准备与提交

1. 将已确认的对外正文写入 Vault 外的 UTF-8 文本文件，保持正文与图注，不额外附加换行。剥离 Markdown 图片语法、发布链接、`## 关联`、HTML 注释等库内信息；标题按已确认的形式转为正文。若需改变措辞或排版，在定稿预览时完成。
2. 将已选图片按顺序下载至 Vault 外临时目录，保留来源对应关系；仅在上传器需要时转换格式，不裁剪原截图。继续复用已有 R2 URL，不重复上传 R2。缺图、无效文件或超过四图都停止。
3. 不带 `--submit` 准备编辑器；发布器通过文件输入框依次提交文件，不依赖系统剪贴板。核对回执旁的 `.text.png`、`.media.png` 和编辑器：全文完整、图数和顺序正确、图片加载完成、发布按钮可用。脚本检查正文逐字匹配，并绑定压缩预览的顺序；压缩后图片与原文件的字节哈希不同是正常现象，不能据此判断传错图。
4. 已获发布授权后，沿用相同文本、图片、来源和回执加 `--submit`，不重复请求确认。脚本再次校验账号、正文和图片，记录提交状态后只点击一次。
5. 获取成功提示中的正式 URL，打开帖子核对全文及全部图片后才标记 verified；正式页面可能将四图显示为横向轮播，检查 `.published-media-1.png` 等逐图截图，不只看首屏。随后回填明确指定的知识库文件。回填失败时保留 verified 和 URL，仅修复回填，不重发。

```bash
SKILL_DIR=/Users/jdy/Documents/skills/jdy_writer
STATE="$HOME/.local/state/jdy-writer/x/<本次内容标识>.json"

# 准备；按已选图数重复 --image，来源路径使用实际 Vault 绝对路径
bun "$SKILL_DIR/x-publisher/x-browser.ts" \
  --text-file /tmp/<本次内容>/approved.txt \
  --image /tmp/<本次内容>/01.png --image /tmp/<本次内容>/02.png \
  --image /tmp/<本次内容>/03.png --image /tmp/<本次内容>/04.png \
  --state-file "$STATE" \
  --source "<Vault绝对路径>/<YYYYMMDD>-x-post-cn.md" \
  --related-source "<Vault绝对路径>/<YYYYMMDD 标题>.md"

# 查看上述预览后，原命令加 --submit；继续使用同一个 STATE
```

回执与截图默认位于 Vault 外，权限为私有；只记录核验所需哈希、状态、文件定位与帖子 URL。发布器不安装依赖；已有依赖不可用时按环境的依赖规则处理。

## 恢复与收尾

- 回执的 `ready` 只表示编辑器准备完成，`submitted` 只表示拿到提交结果；正式页面回读通过才是 `verified`，指定笔记回填完成才是 `complete`。
- `submitting`、超时、响应丢失或进程中断均不能再次点击 Post。先在官方账号页查找，取得确切 URL 后只读核验：

```bash
bun "$SKILL_DIR/x-publisher/x-browser.ts" \
  --state-file "$STATE" --verify-only \
  --published-url "https://x.com/_ThrowException/status/<已核实ID>"
```

- 回执已有 URL 时用 `--state-file "$STATE" --verify-only` 回读并补完回填，不再携带新正文或图片。手动发表同一准备稿也使用此路径。不要删除回执、换一个回执绕过不明确结果。
- 锁遗留时先确认 PID 对应的任务已退出，再检查远端和回执；不自动抢锁。发布前编辑器关闭、内容不一致或部分填入时先检查现状，不能自动清空后重填。
- 回填只向明确指定的笔记追加已核实 URL：X 稿用 `> 发布链接：...`，关联原稿用 `> X 长帖：...`。保留正文、媒体和双链；源文件被其他任务修改时停止覆盖并合并必要的链接。最后按知识库规则检查差异、内部链接和媒体引用。
- 交付时给出正式 X 链接、核验范围和回填结果。只要求草稿时交付 prepared/ready，不宣称已发布。

## Article 与其他形式

用户明确选择 Article 时，使用 `x-publisher/x-article.ts`；封面传 Vault 外本地文件，不传 R2 URL，不为解析标题给 Vault 新增 YAML。检查图片数量、`XIMGPH_N` 残留、预览与正式页面，不能仅凭脚本打印 published 判定成功。该入口及视频、引用帖尚不具备上述单条帖子的回执恢复保障；提交结果不明时人工查证，不自动重试。
